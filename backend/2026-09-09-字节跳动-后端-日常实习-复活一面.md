## 面经正文

一直没反馈默认挂。

针对项目：
1. 你这个混合召回，是哪两种方式的混合召回？
2. 一个文档有很多章节、一级标题、二级标题、正文，你具体怎么切块？
3. 哪部分算子块，哪部分算父块？正文很长的时候你怎么切？
4. 固定长度切块不会把一个完整语义切成两个 Chunk 吗？如果很多 Chunk 的语义都被切碎了，还能召回得准吗？
5. 问RAG切块的其他思路、问chunk size怎么定的
6. 你现在 Hit@1、Hit@3 是这个水平，如果接下来要继续提升 RAG 的召回精确度，你会从哪些方向优化？
7. 对于一个 Query 里包含多个意图/多个目标的情况，为什么第一反应不是让大模型来做拆解或识别，而是用规则？
8. 假设链路是：意图识别 → 多意图识别/拆分 → 并发 RAG → 最终总结，这条链上的 Trace 应该记录哪些东西，才能指导后续优化？
9. 你现在实际上有两条执行路径，对吧？什么类型的任务走哪条路径？具体啥区别？
10. 为什么当时会设计成两个分支、两套不同架构？
11. Plan-and-Execute 和 ReAct 两种 Agent 架构有什么区别？它们各自的优点和缺点是什么？
12. 你整个 Agent 的问题解决率大概是什么水平？有无考虑延时？
13. 你的 Evaluation 方案具体是怎么设计的？能不能详细讲一下从 Case 到 Run 到最终评分的完整流程？
14. Trace 怎么转换成可以被 Grader 使用的评测事实？
15. Eval 集里的 Case 带有时效性。今天用户/商家/订单是状态 A，所以 Query 会走路径 A；三天后状态变化，同一个 Query 已经无法走原来的路径。这种有时效性的 Eval Case 怎么解决？
16. 你的 Tool Registry 是怎么设计的？
17. 假设这个 Agent 不是你一个人用，用户可以自定义工具，怎么支持他们快速注册 Tool？从平台角度，第三方/用户自定义 Tool 应该怎么接进你的 Tool System？
18. 有没有涉及写工具？执行前怎么做 Confirmation？
19. 如果写工具通过网络请求调用其他工程，下游接口超时了，但实际上请求已经在下游成功执行，怎么办？如果下游根本没有这个查询能力呢？如果不能改下游逻辑，怎么办？
