### 一面

已读材料没有写出实际面试日期，也没有写明结果。下面只整理已列出的题意，不补答案，也不补手撕解法。

#### 一、实习经历拷打

1. 询问字节实习经历。
2. 做多 Agent 平台的初衷。
3. 测试用例这个 Agent，是通过自动化用例自己跑出来的吗，跑的目的是什么。
4. 多 Agent 这块自己重点负责哪里。
5. 多 Agent 系统有前后的依赖关系，如果需求 Agent 或开发 Agent 在设计或实现时就有问题，测试 Agent 怎么办。
6. Trace 追踪能力这一块，为什么没有考虑把它做成一个 Agent。
7. 多 Agent 架构编排中遇到的核心问题和卡点。
8. 怎么考量多 Agent 系统是具备泛化能力的？怎么保证它对其他业务也适用。
9. 业务配置层是一个配置的形式，还是一个知识库的形式。
10. 针对模型输出不稳定这个现象，怎么去优化模型。
11. 针对知识库和记忆本身，是业务本身别的记忆更重要，还是人为的配置更重要，还是两者必须结合。
12. 怎么设计训练集和样本集。
13. 有没有实际的需求在多 Agent 架构上完成过。
14. 如果让你从头重新开始设计系统，哪个模块最关键。

#### 二、技术问题拷打

1. 怎么理解「可观测」。
2. Trace 和 Log 之间有什么关系。
3. trace ID 和 span ID 的区别。
4. 如何理解 Trae 的 Harness？觉得哪部分做的不好。
5. 说出一些 Agent 的设计模式。
6. 如何看待测试开发和后台开发的差异。
7. 如果让你使用 Redis 去实现一个延时队列，会怎么实现。
8. 多 Agent 之间怎么通信？有用到哪些协议。
9. TCP、MQTT、UDP。

#### 三、算法

1. 实现 LRU cache 算法。
2. 对于设计 Cache，应该有哪些必要的参数。
3. 如果没有设计容量会怎么样。
4. 如果 cache 都是同时有、它是读多写少的，会考虑怎么优化。
