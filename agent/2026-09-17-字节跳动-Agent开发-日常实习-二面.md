## 速览

- **重点**：RRF 与混合检索、Redis / ES 容灾、多存储一致性、Coding Agent 与 Claude Code 记忆、上下文压缩、排序链表手撕、AI 时代优势是否还在。
- **难度**：高，追问很深，手撕分治卡了很久，已挂。
- **题量**：23 问，另有排序链表手撕。

## 面经正文

1.自我介绍
2.自我介绍结束了？你这两个项目是做着玩的吗？
3.讲讲RRF具体是怎么做的？
4.混合检索怎么体现？向量检索不是只有Redis吗？
5.为什么选用Redis向量检索？
6.没懂你意思，容灾应该是两个向量检索其中一个崩溃才算容灾，两个不同服务怎么称作容灾？
7.思路可以理解，不选ES向量检索为了防止ES崩后整条检索链路崩溃？
8.为什么要同时做Redis向量检索和ES检索？
9.讲讲MySQL、Redis、ES的多存储一致性怎么实现吧
10.你认为这三个服务的分布式事务真的能实现吗？其次有必要实现吗？
11.你为什么做这个Coding Agent？
12.你做的这个是类claudecode或codex吗？有看过它们的设计吗？
13.你觉得claudecode的亮点是什么？
14.有了解claudecode的记忆机制吗？是分层记忆吗？
15.上下文压缩策略是什么？
16.上下文压缩怎么保证任务目标不偏移？
17.单个开发大任务长度就超过上下文限制怎么办？
18.代码开发是子Agent负责吗
19.第一个Agent是怎么拆任务的？举个具体例子
20.手撕：排序链表（实现了mergeTwo和找中间节点，分治卡了半天没写出来）
21.先到这里吧，再问你几个问题。你觉得自己的优势是什么？
22.现在AI发展这么快速，训练过的语料量也很大。关于架构设计可以交给多个Agent进行讨论决策，多数情况是优于我们这些普通人的思路的，那你觉得这个优势还存在吗，你认为有什么破局之路吗？
23.后续想法是读研还是工作？一周可到岗几天？能实习多久？
24.反问：AI时代破局之路。（挺有收获的）

拷打完在椅子上瘫坐了二十分钟，从未体会过如此深沉的无力感。趁着劲头一口气跑了十公里，回宿舍复盘思考下一步。感觉面试能追问的角度近乎无限，但人脑的上下文额度有限，而且还有艾宾浩斯曲线这种不重复就容易遗忘的机制存在。现在面试前属于是拆东墙补西墙，多学多记尽量扩大记忆重心与追问角度的重合度。但一落到底层实现细节和陌生追问角度就容易宕机，目前逻辑链路和架构取舍答得还行，先把重点放在原理层深挖试试
