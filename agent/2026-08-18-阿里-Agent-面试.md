## 面经正文

以下为内容整理，只保留问题含义和已核到的设计点，不是逐字原文，也不整段改写图中作答。

自我介绍、项目介绍，以及如何把以技能或脚本为主的 Agent 改造成对外提供服务的后端，并设计整体架构。

继续追问架构分层：接入、会话状态、执行循环、工具注册与隔离、记忆存储、观测等职责如何拆分；会话状态如何外置并支持横向扩展；长任务与流式响应如何处理。

Agent 后端处理耗时不定的工具调用时，怎样安排并发、超时和用户取消。已核到的设计点包括区分 I/O 密集与 CPU 密集工作、限制并发和资源，以及让取消信号传到实际工具执行层。

前端需要看到模型逐段输出时，服务端到浏览器如何传输。图中讨论 SSE、事件分块或刷新，以及浏览器使用事件流或可读流消费、代理缓冲对流式效果的影响。

短期会话记录和长期记忆的底层如何组织。已核到的设计点包括：会话历史按 session 标识外置保存，短期上下文用滑窗或摘要压缩；长期用户偏好与关键事实进入向量或关系存储，按当前问题检索后写回上下文，并异步更新。

Agent 工具调用的安全边界：如何防止 Prompt Injection 或越权，如何处理网页或工具返回的非可信内容，以及如何做沙箱、最小权限、参数校验、工具白名单和高风险操作保护。

大量用户并发调用时如何保证可用性。已核到的设计点包括入口与模型或工具侧限流、优先队列与并发上限、对可重试失败采用有边界的重试、熔断、备用模型或缓存和降级。

如何控制模型调用成本。已核到的设计点包括检查上下文和工具结果造成的输入 token、限制无效生成、压缩或裁剪历史、利用语义缓存及稳定提示前缀缓存，并按用户或会话监控 token 与成本。
