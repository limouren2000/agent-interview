# 小红书agent实习一面二面面经

> 小红书 · Agent开发 · 实习一面二面 · 发帖 2026-11-04 · 作者 爱吃雪糕🍦 · 来源：[小红书](https://www.xiaohongshu.com/explore/6aeaeab0000000000e02d46f)（一面）、[小红书](https://www.xiaohongshu.com/explore/6aeaf004000000000e027fe3)（二面）

## 速览

- **重点**：一面问 Agent 链路、端到端延迟和体感优化、Jev / Decision Model、编排稳定性与灵活性、数据快照版本、SQL 工具重试熔断，以及结合文档讲 RAG，手撕回文链表；二面问 Personal Agent 和 Proactive 交互，还有多模态场景里的代词指代消解。
- **难度**：实习。一面面试官比较和善，问题贴合项目；二面产品思维较多，作者觉得准备不算充分，但收获很大。结果均未说明。
- **题量**：一面工程与延迟约 9 问，另有编码习惯问答和 1 道手撕；二面约 10 问，无手撕。看不出是暑期实习还是日常实习，故标为实习。

## 面经正文

小红书agent实习一面面经

————Agent 工程、延迟与稳定性————
介绍一下自己，以及此前做过的有代表性的项目。
举一个具体场景，完整讲一遍从用户输入到生成结果的 Agent 链路。
对于复杂问题，从输入到获得合理完整回答，端到端延迟 P50 大概有多少？
如果开发面向 C 端用户、需要实时交互的 Agent，用户不能等待这么久，你会从哪些方向优化体感延迟？
你提到了 Jev / Decision Model，它负责输出决策。你会怎样让它与传统大模型结合，参与 Agent 推理？举一个熟悉的场景。
对重点场景，我们希望有稳定、可预期的编排；对通用场景又希望保持灵活性。如何权衡两者？
用户先问一个问题，两分钟后又问另一个相关问题，但期间快照已更新。第二轮应该用哪个数据版本？
如果数据分析 Agent 连续三次用相同 SQL 工具得到同样错误，接着又产生相同调用，你会在哪一层处理？重试、熔断、终止如何控制？
给定一个包含正文、章节和表格的技术文档，请结合它解释你的RAG流程。为什么每一步必要？各有什么作用？相比直接把整篇文档交给模型有什么优势？
————编码环节与其他————
平时经常使用 Vibe Coding 吗？
是否很久没有脱离 AI 独立编程了？
手撕 回文链表

======总结======
面试官很和善，问的问题也都比较贴合实际项目场景，很会引导人

小红书agent实习二面面经

————方向理解与产品场景————
最近 Personal Agent 的浪潮你关注过吗？
说说你对这些 Personal Agent 产品的感受和评价。
假设加入小红书团队，我们想做一个具备小红书竞争优势的 Personal Agent。你准备怎么做？你认为优势是什么？
你提出 Proactive 交互。请举一个实际的 User Story：作为用户，什么样的主动交互能打动你？
假设已经有一个以 React 为主的 Agent 系统，由你负责添加 Personal Agent 的 Proactive 功能。你会如何在现有架构上补充，还是新建独立架构？
请画出这个 Proactive 模块的架构图和数据流，并解释思路。
在主动交互前，如何提升系统对用户需求推测是否正确的判断能力？
怎样判断“现在适不适合打扰用户”？如何提高这项判断的准确性？
个体用户的反馈数据量真的足够吗？无论使用另一个模型调节，还是模型自我调整，这么少的数据能产生有意义的变化吗？
————多模态上下文与代词指代消解————
场景题：用户早上通过视频向 Agent 展示一套键鼠设备，并表达“这个真好看”的偏好。十分钟后询问“刚才那个可以用在 iPad 上吗”，晚上又说“我是不是应该早上把它买了”。如何识别这些代称，匹配到正确的实体和上下文？
无手撕
======总结======
这场面试问了非常多产品思维相关，提的问题也都很有意思，自己准备的确实不算非常充分，但是收获确实很大，尤其是现在这个时代，纯做开发其实价值会越来越低，还是要尽量补充一些产品思维，关注用户真正需要的东西。

我非常推荐大家在面试结束的反问时问这样一个问题：作为面试官，你希望候选人有什么样的特质或能力？有两个好处，一个是可以对比一下面试官给出的答案和自己这场面试的表现，基本就能当场判断自己是不是会通过；另一个好处就是会给自己后续的学习一个很好的方向，也会对自己面试时的状态得到一个很清晰的反馈，我遇到的大多数面试官在这个环节都是很愿意和你聊一聊的，不管你前面的面试表现如何。
