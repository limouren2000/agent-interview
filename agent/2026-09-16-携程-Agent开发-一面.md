# 9.16 携程agent开发一面

## 速览

- **重点**：多步时序推理数据链路、Top-K 与停止条件、四元组知识图谱、SFT 与强化学习奖励、Harness 与开源、Java 锁和 CountDownLatch。
- **难度**：中等，无手撕，过程中面试官频频皱眉但已进入二面。
- **题量**：26 道。

## 面经正文

1.请简单介绍一下个人经历。
2.科研项目和实践项目是与导师合作完成的吗？
3.你平时是否购买大模型或 AI 编程工具的订阅？使用的是官方订阅还是第三方 API？
4.具体使用的是什么模型？
5.学校是否提供大模型调用费用或报销额度？
6.你希望重点介绍哪个项目？（项目1）
7.请举一个必须经过多步时序推理才能回答的问题，并说明 Agent 从规划、思考、工具调用到最终回复的完整数据链路。
8.为什么普通 RAG 的一次 Top-K 检索无法解决问题？为什么最终选择 Top-15？
9.Agent 每轮都会继续检索，它如何判断应该停止检索？
10.每轮检索结束后，是否会对检索数据进行校验？
11.为什么时序知识图谱采用四元组，而不是普通 RDF 表达？
12.如何将事实映射成四元组？四元组是在何时建立的？
13.项目1 的方案是否适用于普通公司的知识库问答系统？
14.SFT 为模型增加了什么能力？为什么只使用 Prompt 和 Agent 不够？
15.为什么把检索覆盖度纳入强化学习的奖励函数？
16.如何证明准确率提升来自 SFT，而不是来自 Agent 增加了检索轮数？
17.项目1是否有实际落地场景，还是仅用于科研？
18.是否阅读过 Harness 相关开源项目的源码？
19.是否做过开源项目或在 GitHub 上发布过自己的工程项目？
20.面试复盘网站是否已经开始实现，还是仅停留在想法阶段？
21.平时对哪些开源项目比较感兴趣？
22.秋招面试中，Java 底层知识是否经常被问到？
23.Java 中常见的两种同步锁实现是什么？它们有什么区别？
24.公平锁和非公平锁哪个性能更好？为什么？
25.在必须等待三个线程全部完成后再继续的场景中，如何使用 CountDownLatch、CyclicBarrier 和 Semaphore？
26.你对携程的业务有什么想了解的？
