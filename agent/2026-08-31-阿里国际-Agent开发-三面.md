## 面经正文

自我介绍。
你最近这一段的工作经历展开吧
从业务上面看，你们的整个业务方案有哪些？以及你们的产品提供给业务方有哪些形态和能力？
你们的业务上，会做哪些维度的处理？举一个业务case
对于在线链路和离线链路（同步/异步）的整个架构是怎样的？
核心就是要保证在线链路的性能与稳定性，这一套整个架构是怎样的？你怎么保证性能？怎么保证稳定性？
你们本身业务是怎么做到算法模型、策略规则配合
在没有大模型出来之前，你们的技术路线是？
你在里面大概负责哪一块？
模型服务包装成在线 RPC 服务不就行了吗？为什么还需要工程化？
你是面向每个业务都给它包装一个，还是说是一个标准的通用模型服务设计？
如果偏向业务的产品，为什么工程化不能变成标准化的？来一个业务产品对接一次的价值是什么？
算法同学把模型开发出来，模型部署的工作是你们自己去搞的？
你们本身有模型平台吗？模型部署到模型平台，用公司标准的服务方式访问，这个一定是标准的了。那除了针对性做一些业务产品接入，你过去最核心的工作或建设的能力包含哪些？
做重构，核心就是重构前的架构和重构后的架构差异是什么？
项目技术方案是什么？能展开讲一下技术架构设计吗？
运行态下，配置调度的具体过程是怎样的？
所以整个运行引擎是一个 C++ 的平台？你只是负责配置平台，还是对整个执行引擎也有相应开发？
你交付的最终是一些 Lua 脚本。为什么选择 Lua 脚本去做这个事情？
讲一下 Agent 这一块的整个设计是怎样的吗？
你如果用 Skill 去做流程描述，怎么保证它是按照 Skill 描述的步骤一步一步执行的？如果存在跳过某个环节呢？
你的 Harness 是怎么建的
你做过除了研发提效内容，在业务 Agent 研发里做过哪些业务类型的 Agent 应用？
在 Agent 整体架构设计里面，你认为最核心的模块是什么？
你有没有做过用 Agent 去做整个决策规划？你想把推理判断全部交给 Agent 吗？怎么放大它的能力做长任务推理和执行，任务规划得准确、拆解清楚？
关于做 Agent 工程，你觉得有哪些非常关键或者需要注意的事项？
