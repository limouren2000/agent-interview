## 面经正文

1.项目拷打：介绍下mutilagent的项目
Multi-Agent（多智能体）项目是指由多个自主、协同或竞争的智能体（Agent）组成的系统，每个Agent具备感知环境、决策推理、执行动作和与其他Agent交互的能力。

典型项目如Meta的CICERO（首个在《外交》游戏中达到人类专家水平的多智能体系统）、Google的AutoGen框架、Microsoft的Semantic Kernel多Agent编排方案，以及开源项目LangChain + CrewAI构建的任务型多Agent协作系统（如市场分析Agent + 报告生成Agent + PPT制作Agent串联工作流）。

一个典型的校园招聘级Multi-Agent项目可以是：基于LLM驱动的“校园求职助手”系统，包含岗位检索Agent（调用学校就业网API）、简历优化Agent（基于用户PDF简历+JD做针对性改写）、模拟面试Agent（实时语音/文本问答+反馈打分）、进度追踪Agent（自动同步BOSS直聘/实习僧状态并提醒），四者通过统一消息总线（如Redis Pub/Sub或自定义AgentMessage协议）通信，并由Orchestrator Agent进行任务调度与异常回滚。

3.mcp和skill的区别
MCP（Model Calling Protocol）和Skill是两种不同层级、不同定位的AI能力抽象概念。

MCP是一种标准化的协议规范，用于定义大模型与外部系统（如工具、API、数据库、插件等）之间交互的通用通信接口；而Skill（技能）是具体的功能性能力单元，通常指一个可被调用、完成特定任务的原子化能力模块（例如“查天气”“发邮件”“解析PDF”），它依赖于某种执行机制（如函数调用、API调用或代码执行），但本身不规定通信协议。

4.二者谁占用上下文窗口比较大
在相同参数量和输入长度下，Transformer 解码器（Decoder-only）架构比编码器-解码器（Encoder-Decoder）架构通常占用更大的上下文窗口（即显存中用于缓存历史 token 的 KV Cache 空间），尤其在自回归生成阶段；但若仅比较模型结构本身的静态参数内存（不含 KV Cache），则 Encoder-Decoder 模型因双塔结构（encoder + decoder）参数更多、中间表示维度更丰富，其静态上下文占用更大。

需明确“上下文窗口占用”指代的是：

（1）推理时动态增长的 KV Cache 显存，还是

（2）模型加载时的静态参数+激活内存。绝大多数校园招聘面试语境下（尤其大模型方向），该问题实际考察的是推理时的 KV Cache 内存开销，此时 Decoder-only 模型（如 LLaMA、GPT 系列）占用更大。

5.langgraph和langchain的区别
LangChain 是一个面向大语言模型（LLM）应用开发的通用框架，核心定位是提供模块化工具链（如提示词管理、记忆机制、链式调用、代理Agent抽象等），用于快速构建基于LLM的应用；LangGraph 是 LangChain 生态中专门用于构建有状态、多步骤、循环可控的图结构工作流（Stateful Graph Workflows） 的扩展库，它并非 LangChain 的替代品，而是其在复杂 Agent 编排场景下的增强实现——本质上，LangGraph 是 LangChain 的子项目（官方维护），解决了 LangChain 原生 Chain 和 Agent 在建模非线性、带循环、需状态持久化和条件分支的流程时的表达力不足问题。

6.如果要你做一个agent，获取爆款内容，生成图片，该怎么做
构建一个爆款内容感知与图像生成Agent，需分四层实现：

1）爆款内容采集与识别层（多源爬取+热度指标建模）；

2）内容理解与结构化层（LLM驱动的语义解析+关键元素抽取）；

3）图像生成指令工程层（Prompt优化+多模态对齐约束）；

4）生成-反馈闭环层（A/B图评估+人工/模型反馈强化）。核心不是单点技术堆砌，而是建立“热度信号→语义意图→可控视觉表达→效果归因”的端到端可解释链路。
