## 面经正文

快手基础模型部二面，问题更偏向于模型应用一些。
1. 模型生成的结果中满足规则的方案很多，怎么知道用户更喜欢哪一个？
我做的 Agent 要根据预算、人数、偏好等约束生成方案。面试官问：满足预算的组合有很多，你怎么判断哪种更好？用过真实线上反馈吗？
我的回答：当时分两层做，先确保方案符合平台硬规则、能够执行，再用评分细则和 LLM Judge 评估质量，训练后做人工盲评。
面试官继续追问：评分规则是你们定义的，标注员的偏好也不等于用户偏好。真实反馈有没有用起来？
这里确实有缺口：当时主要做从零到一的能力建设，人工评价用于验收，线上反馈还没有充分用于训练。被问到重做会优先改什么时，我提到补充用户画像、记录用户反馈，并把筛选后的数据回流训练。
复盘补充：
我会先区分“能执行”“满足明确需求”和“用户更喜欢”，分别评估。
然后记录用户直接接受、修改、重新生成、放弃等行为，结合明确反馈抽查原因。例如改掉一个选项，是不喜欢，还是库存变化？
线上做随机 A/B，对比任务完成率、用户修改次数，同时关注延迟和失败率，结合多项指标判断体验变化。参考
我也不会直接把点击、下单当成满意标签，还会检查价格、促销等因素。回流训练时保留上下文和候选方案，避免只收集成功结果，却不知道用户为什么选择它。
2. 内外部训练数据 1∶1，怎么证明这个比例好？
我的回答：加入外部工具调用数据，是希望丰富问题表达，让模型学习读取工具说明，减少对固定工具的依赖。当时比较了数据子集和配比，最后采用 1∶1。
面试官质疑：这个比例听起来像凭经验定的，实验依据够不够？
我也承认，实际尝试的配比不多，效果可以就继续推进了，没有充分验证最佳比例。
复盘补充：
更准确的表述应该是“已测试配置中较好”，并说明测试范围。
如果重做，我会先明确比例按样本数还是 token 数计算；固定初始模型、训练 token 预算和其他配置，比较纯业务数据及几档混合比例。
评测拆成业务成功率、工具选择、参数正确性、未见工具泛化，避免总分掩盖某项能力退化。用验证集选比例，再看独立测试集；差异小时重复实验，检查是否只是随机波动。
另外还问了：主 Agent 为什么同时负责路由和工具选择、重做项目会优先改什么、过程奖励与信用分配。

手写题是单头 Attention。
