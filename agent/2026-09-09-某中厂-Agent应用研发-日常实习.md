## 速览

- **重点**：混合编排和别的 Agent 有什么不一样，工具为什么包含结果分析，高精度、强确定性场景里要不要用 Agent，以及幻觉的预防和兜底。还问了 Harness 里的 Session、Memory、Sandbox，多轮上下文怎么维护，有没有滑动窗口或长上下文压缩。后半也问到缓存穿透、击穿，以及逻辑过期和加锁重建分别适合什么场景。

- **题量**：18 问。

## 面经正文

8月底面的了，虽然时间很短但是问题非常有价值，第一次思考agent到底在什么场景下是需要的。

1. 请先做一下自我介绍。
2. 你提到混合编排，这不是很多 Agent 都有的吗？你这里有什么不一样的地方？
3. 你这个 Agent 具体会处理哪些任务？
4. 你说挂载了几个工具，这些工具分别是做什么的？
5. 工具一般是处理固定流程的，你这个结果分析为什么也做成 Tool？
6. 结果里的异常，是大模型判断，还是工具内部通过规则判断？
7. 既然这些规则用 Python 脚本就能处理，为什么还要用 Agent？
8. 在这种高精度、强确定性的场景里，大模型有幻觉，那是不是本身就不适合用 Agent？
9. 对于大模型偶尔出现的幻觉和错误，你有什么预防或兜底机制？
10. 如果最后还是需要人工复查，那相比直接用 Python 工具批处理，Agent 会不会反而多了一层、显得多余？
11. 你后端项目里，高并发场景下缓存穿透、缓存击穿是怎么处理的？
12. 逻辑过期和加锁重建这两种方案分别适合什么场景？
13. 你了解过“小龙虾”或者 Hermes 这类 Agent 框架吗？
14. 你对最近开源的 Harness / Agent Harness 有什么了解？有实际用过吗？
15. 你的 Agent 项目具体调用的是什么大模型？Embedding 和 Rerank 用的是什么模型？
16. 你现在的系统支持多模态吗？比如 PDF、图片、Doc 这些文件格式？
17. Agent Harness 里比较重要的 Session、Memory、Sandbox / 安全控制，你这边有做什么处理吗？
18. 你现在的多轮上下文是怎么维护的？会保存哪些信息？有没有做滑动窗口或长上下文压缩？
