## 速览

- **重点**：背景匹配与跨域迁移、好的 Agent 范式（安全约束、工具调用、长程编排、多模态、badcase 回流）、业务场景落地、字符串共同前缀手撕。
- **难度**：氛围轻松、节奏快，约 40 分钟，偏能不能干活而不是纯八股；作者发帖时已入职第六天。
- **题量**：结构分三部分，开放性问题与业务场景为主，另有手撕 1 道。

## 面经正文

入职第六天，来给大家分享一下之前面试的整体流程和考察重点。

面试整体结构
面试官开场就说了大概三部分：
1. 自我介绍+项目论文经历
2. 面试官介绍部门和岗位
3. 在线笔试/技术问答

整体氛围比较轻松

考察重点
1 背景匹配度盘问
• 会确认导师是否知情并同意实习
• 会问你的研究方向和岗位业务方向的差异，看你能不能把已有经验迁移过来
• 建议提前想好“我的能力和这个岗位是同构的”这种论述逻辑

2 Agent 开放性问题（重点！）
高频题：“你觉得一个好的 Agent 范式需要具备哪些能力/组件？”

可以从这几个角度答：
• 能力边界与安全约束：哪些能做、哪些是红线（尤其涉及资金/交易场景），约束框架怎么设计
• 工具调用：Agent 能调用哪些工具、如何编排
• 多步流程编排：长程任务的状态管理、幂等
• 多模态输入：文本 + 图像 + 结构化信息的融合理解
• badcase 回流与持续迭代：评测和数据闭环

还问了agent社区近况，问agent上下文压缩的sota，两轮都问了。
问了简历上后训练相关的，总之很结合业务需求来问，项目不是特别深挖。

3 业务场景理解
• 会给你讲一个具体业务场景（多模态客服/售后类），看你怎么把 Agent 技术落地

4 手撕：字符串共同前缀
——————————————————————————
一些建议：
• 提前想好“自己研究方向如何如何跨域迁移的说服话术
• 论文经历别只讲内容，要讲怎么迁移到业务上
• 对方岗位会主动介绍 JD，提前研究一下，面试时主动对齐会加分
面试节奏很快，前后大概40分钟，问的问题都比较务实，偏向“能不能干活”而不是纯八股。

祝大家面试顺利！
