- **重点**：RAG、记忆与上下文、工具调用 / MCP / Skill、Agent 规划、评测。

## 面经正文

先自我介绍，拷打了一点非常简单的java八股，接下来根据我的项目问了以下ai问题
很多的点我实际面试中没回答上来，下面的回答仅供参考

1. RAG 单轮和多轮推理的核心差别在哪里？
回答： 单轮 RAG 只需要围绕当前问题完成“检索—生成”；多轮 RAG 还要理解历史对话中的指代、省略和上下文依赖。工程上通常需要做问题改写、会话状态管理和历史信息压缩，避免无关对话干扰检索结果。

2. 需求匹配代码的场景，单轮还是多轮更合适？
回答： 如果需求明确，只是查找相关代码，单轮检索通常足够。若需求存在歧义，需要根据搜索结果继续补充条件、定位调用链或逐步缩小范围，则更适合多轮。核心取决于任务是否依赖前一步结果，而不是越复杂越好。

3. RRF 融合多路检索结果的原理是什么？
回答： RRF 不直接比较不同检索器的原始分数，而是根据文档在每个结果列表中的排名打分，常见形式为 1 / (k + rank)，再将各路得分相加。它能融合关键词检索、向量检索等不同量纲的结果，实现简单稳定的混合召回。

4. RRF 中的 k 一般取多少？不同检索源需要加权吗？
回答： 常见默认值是 60，但不是固定答案，需要结合评测集调参。若各检索源质量相近，可以直接融合；如果某一路数据更权威或历史效果更好，可以使用加权 RRF，但要防止某一检索源长期垄断排序。

5. 初排已经给出顺序，为什么还需要重排？
回答： 初排通常依赖关键词或向量相似度，速度快、召回高，但只能进行较粗的语义匹配。重排模型会同时理解问题和候选文档，进行更细粒度的相关性判断，把真正能回答问题的内容提升到前面。

6. 粗排和精排分别有什么作用？为什么不能全量精排？
回答： 粗排负责从海量数据中快速召回候选，强调高召回率；精排负责对少量候选重新打分，强调准确率。精排模型计算成本和延迟较高，对全部文档逐一计算在线服务难以承受，因此通常采用“Top-K 召回＋Top-N 重排”。

7. Markdown、PDF 怎么切分才能保留文档层级？
回答： Markdown 可以按照标题级别、段落和代码块切分，并在元数据中保存完整标题路径。PDF 需要结合目录、页码和版面分析识别章节，同时单独处理表格、图片和跨页段落。切分时应保留父子关系和相邻块信息，避免只按固定字符数生切。

8.Agent 处理文档时超出上下文窗口怎么办？
回答： 可以采用递归切分、按需检索和分层摘要。先将长文档拆成小块分别处理，再汇总局部结果，形成 Map-Reduce 或树状总结；同时只把当前任务真正相关的内容放入上下文，而不是一次性加载全文。

9. Skill 和 MCP 扩展 Agent 能力的本质区别是什么？
回答： Skill 是面向具体任务的能力封装，可能包含提示词、工具、流程、代码和输出规范；MCP 是统一的连接协议，用于让 Agent 发现并调用外部工具、资源和服务。简单来说，Skill 描述“如何完成任务”，MCP 解决“如何标准化接入能力”。

10. Agent 如何记住历史对话？Memory 模块如何运行？
回答： 短期记忆通常保存当前会话消息、任务状态和工具结果；长期记忆则将稳定偏好、历史事实等存入数据库或向量库。新问题到来时，系统检索相关记忆并注入上下文，同时要处理信息更新、冲突、过期和隐私问题。

11. 对话轮次增加导致上下文膨胀，有哪些解决方案？
回答： 常见方案包括滑动窗口、历史对话摘要、按需检索长期记忆，以及删除重复或低价值的工具结果。工程上应设置 Token 预算，优先保留系统规则、当前任务和关键事实，而不是机械保留全部历史消息。

12. ReAct 推理与行动交替的完整流程是什么？
回答： 模型先根据问题判断下一步行动，再调用搜索、数据库或业务接口等工具；工具返回观察结果后，模型基于新信息继续决策。这个过程不断循环，直到信息足够并生成最终答案。生产环境还需要设置最大步数、超时、权限校验和失败兜底。

13.ReAct 和 Agent Loop 都是循环，本质区别在哪里？
回答： ReAct 是一种具体的 Agent 策略，强调“推理—行动—观察”交替执行；Agent Loop 是更通用的运行框架，负责管理模型调用、工具执行、状态更新和终止条件。Agent Loop 可以使用 ReAct，也可以加入规划、反思、并行执行或人工确认等其他机制。
