多线程 count++ 执行 1000 次结果小于 1000？
count++不是原子操作，它拆分为三步：

1. **读**：从主内存把 count 读到线程工作内存（load）
2. **改**：工作内存中执行 +1 运算（use、assign）
3. **写**：把新值写回主内存（store、write）
多线程下，两个线程会发生**读‑改‑写交错**，出现**写覆盖（丢失更新）**，最终总计数小于预期 1000。

### 追问：什么是写覆盖？还原两个线程交错完整现场

假设初始 `count = 0`，线程 A、B 同时执行 `count++`

1. 线程 A：读取 count=0 到本地，准备 + 1
2. **CPU 切换，线程 A 暂停**
3. 线程 B：也读取 count=0 到本地，执行 + 1，得到 1，写回主内存 → 主内存 count=1
4. **切回线程 A**，线程 A 手里还是旧的本地值 0，执行 + 1 得到 1，写回主内存 → 主内存 count=1

👉 两个线程各做一次自增，结果只变成 1。**线程 A 的写入把线程 B 的更新给覆盖掉，就是写覆盖（丢失更新）**。两个线程都读到同一个旧值，各自计算后先后写回，后写的覆盖先写的结果，计数丢失。
解决方案 ： 1.使用 synchronized 同步锁， 让只有一个进程可以count++  2. 使用原子类 AtomicInteger
