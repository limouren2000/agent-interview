## 速览

- **重点**：跨部门接口对接、工具过多时的处理与检索、测评准确率、端到端业务链路、与 MCP / LangChain Tools 的区别、Prompt 过长与超长工具返回、Coding Agent 优化、LRU Cache。
- **难度**：中等，作者感觉答得不好，有几问支支吾吾。
- **题量**：12 道，另有 LRU Cache 手撕。

## 面经正文

好久没面试啦，感觉答的不好，好几个问题答的支支吾吾的

附面经：
1、自我介绍
2、介绍百度实习时如何和前端/其他部门做接口对接，具体遇到什么问题？
3、Agent工具过多时你是怎么处理的？比如接口数量太多怎么解决？
4、最终的效果怎么样？准确率达到了多少？怎么测评？
5、项目中端到端的业务逻辑是什么？用户到底想做什么？整个数据流和功能效果是什么？
6、处理流程可以讲一下吗？整体链路是怎样的？
7、你这个工具调用和 MCP、LangChain 的 Tools/Skills 有什么比较大的区别？
8、假如现在有100多个工具，AI想调用的时候，能找到自己想要的接口吗？怎么保障？
9、当Agent拥有大量工具时，如何避免工具描述导致Prompt过长？
10、如果工具返回的数据量过大，超过上下文窗口限制，应该如何处理？
11、如果出现当前已给工具无法解决的问题时，怎么去解决的？
12、如果让你优化一个Coding Agent系统，你会优先从哪些方向入手？
13、手撕：LRU Cache
