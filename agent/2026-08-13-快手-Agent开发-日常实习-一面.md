# 快手Agent开发一面

> 快手 · Agent开发 · 日常实习一面 · 发帖 2026-08-13 16:50 · 作者 等个消息橘子 · 来源：[牛客](https://www.nowcoder.com/feed/main/detail/ce1b038c57c44cc08464561a8cfa0434)

## 速览

- **重点**：RAG、记忆与上下文、工具调用 / MCP / Skill、手撕算法、Agent 规划。
- **难度**：中等。
- **题量**：3 道左右。

## 面经正文

是日常实习
我本来以为这场会重点聊 Agent 项目，比如 ReAct、RAG、MCP、记忆这些。结果面完发现，大厂问 Agent 岗不是让你表演“我会调大模型 API”，它会顺着你的项目一路问到后端基础、并发、缓存、系统设计。
先说大概流程：自我介绍后，面试官直接问我的 Agent 项目是不是实习项目，有没有真实上线，用户量和调用量大概多少。我这里答得有点虚，因为项目是个人项目 + 校内场景，没真正接业务流量。
然后开始拷打项目：
你的 Agent 为什么要有长短期记忆？
什么信息进长期记忆，什么信息只放短期？
上下文窗口不够了怎么办？截断、摘要压缩、检索召回怎么取舍？
你这个 Agent 是 ReAct 还是工作流？为什么？
工具调用失败了怎么处理？
如果检索结果互相矛盾，模型该信谁？
这些我还能勉强接住。真正开始寄，是后面突然切到后端基础。
他问了 Go channel 是不是并发安全，channel 和 mutex 的区别，GMP 调度，本地队列为空时怎么偷任务。然后又问 Redis 为什么快、支持哪些数据结构、怎么做类似淘宝搜索框的实时模糊搜索。最后还问了扫码登录完整流程、服务注册发现、Nacos/Consul 心跳。
我当时脑子里只有一句：不是，哥，我不是来面 Agent 的吗？
但现在复盘，面试官其实没跑题。Agent 中台本质还是工程系统。模型只是其中一环，真正上线要考虑：并发、缓存、工具超时、权限、日志、状态流转、服务稳定性。你 Agent 跑得再花，后端底盘答不上来，人家也不敢让你接中台。
手撕题也不是很算法，是偏工程：给 100 个任务 ID，控制最大并发数为 3，模拟并发调用外部接口。这个其实就是在看你会不会写限流/并发控制，跟 Agent 批量调用工具还挺像。
给准备 Agent 岗的朋友们一个提醒：别只刷新概念。至少准备三条线：
1、Agent 线：ReAct、RAG、Memory、Tool Calling、MCP、安全护栏。
2、后端线：并发、Redis、MySQL、服务发现、登录鉴权、消息队列。
3、项目线：有没有上线、失败 case、怎么观测、怎么降级、成本和延迟怎么控。
如果你是后端转 Agent，优势其实是有的。但前提是你能把“Agent 不是玩具 demo，而是一个会调工具、会失败、要被治理的后端系统”讲清楚。
